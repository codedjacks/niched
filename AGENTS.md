- Game logic lives in src/game (questions, scoring, selection, storage, hooks) separate from UI in src/components/game; rarity goes through the RaritySource interface; frequencyRarity uses real answer counts from the backend once a question has MIN_SAMPLES answers, else the curated tier, so new questions still score sensibly.
- Ranked daily scores and answer counts are written only by server functions that re-score typed answers server-side (judge.server.ts verifyAnswer), so clients can't fake points; guests can play but only signed-in accounts rank.
- Raw game tables are owner/participant-scoped; public rankings and question-scoped frequency data use bounded projection RPCs, so public features never require unrestricted raw-record access.
- Avatars are preset sticker emoji ids stored on the profile, because public storage buckets are blocked for this workspace.
- Topic challenges use a separate question registry, topic-scoped local progress, and shared Play/Results screens; preserve the published daily bank order so old ranked answers still verify.
- Daily scheduling uses frozen historical pools and append-only seeded reviewed batches; never shuffle new content into an existing scheduled batch, never recycle exhausted questions, and return no round unless seven fresh questions remain so historical scoring and stateless verification stay consistent.
- Each reviewed supply expansion has its own frozen question module and seed appended after earlier batches; exclude all reviewed batches from the legacy pool so adding content cannot move historical questions.
- Pause the question countdown while submitted answers are being graded, and preserve retryable answers after checker failures so service latency never consumes a player's answering time.
- From AI_DAILY_FROM onward the Daily Challenge is AI-written: one round per day stored in ai_questions (generated once under an ai_daily_rounds DB lease, pre-generated by the scheduled /api/public/jobs/ai-daily route, otherwise on first request), with prompts deduped against every bundled and past AI prompt; ranked scoring and the answer checker load AI questions from the database so server-side verification stays authoritative. Earlier days keep the static schedule so old results still verify.
- Topic challenges (Sports/Entertainment/History) also get one AI-written round per topic per day (ai_questions.track + ai_topic_rounds lease), deduped against all prompts; the bank deck is only a fallback when generation fails, so topics stay playable.
- Ranked saves go through src/game/ranked.server.ts; copies without the admin database key (e.g. self-hosted niched.site) forward the player's sign-in token to the main site's /api/public/ranked, which verifies it and re-grades, because the admin key can't leave Lovable Cloud.
- Niched is sports-only: from SPORTS_DAILY_FROM the main AI daily is written as sports and Practice draws from the sports pool; Entertainment/History/Sports topic pages are retired (old topic rows and challenges.ts stay so past ids still parse).
- Daily mini-games (grid, mystery, higher-lower) use curated data in src/game picked by date seed via daily-games.ts, with per-game local progress, so everyone gets the same puzzle; Grid guesses outside the curated player list are fact-checked server-side by the AI (grid.functions.ts) so any real NBA career counts.
- Real player facts (NBA/NFL/MLB/NHL teams, awards, draft, birthplace, career totals) come from ESPN's public athlete endpoints via src/game/players.server.ts and are cached in sports_players/sports_player_aliases; Daily Grid checks this before falling back to AI, Higher/Lower swaps in verified career totals, and Mystery Athlete resolves typed names through it, so all games share one source of truth.
